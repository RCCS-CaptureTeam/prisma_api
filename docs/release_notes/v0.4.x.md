# v0.4.9

https://github.com/RCCS-CaptureTeam/prisma_api/releases/edit/v0.4.9

_Released 2026-11-11_

### AutoPrism

- Each AutoPrism row can record the exact files its job read and wrote, with their checksums, and rows from jobs with the same files share one provenance record on the platform; needs prisma_cloud 0.6.24 or later (`prisma_api.provenance_files`, `meta_provenance={"files": ...}`)
- Store a run's whole provenance bundle (e.g. a `.tar.gz`) on the platform and download it again, checked by SHA-256 on both sides; needs prisma_cloud 0.6.24 or later (`api.v2.upload_computation_run_bundle`, `download_computation_run_bundle`)
- New warning when stored results point to an input CIF the platform doesn't have, listing each structure and md5 so you can upload the missing files; the upload summary also lists them (`prisma_api.PrismaMd5WithoutCifWarning`, `md5_without_cif`)
- CIF uploads now send each file's md5, which the platform checks against the content and records with the structure (`api.v2.upsert_autoprism_cifs`, `upsert_autoprism_collection`)

### Datasets

- Dataset zips whose manifest has no file checksums (made by hand or by an older `prisma-dataset pack`) are refused from prisma_cloud 0.6.24; re-pack them, or apply them anyway with `allow_unverified=True` (`api.v2.ingest_dataset`, `prisma_api.dataset_package.upload`)

# v0.4.8

https://github.com/RCCS-CaptureTeam/prisma_api/releases/edit/v0.4.8

_Released 2026-11-09_

### Materials & structures

- Read and write per-material properties and model parameters, such as fitted isotherm models, pellet properties, prices and LCA links, with any JSON value plus units and a reference; needs prisma_cloud 0.6.23 or later (`api.v2.get_material_properties`, `upsert_material_properties`)
- Material property uploads can remove a category's old entries that are no longer listed, and report rejected rows as warnings or errors (`prune=True`, `raise_on_error=True`)
- Material properties also appear, read-only, as a `properties` section of material bundles from prisma_cloud 0.6.23 (`api.v2.get_material_bundles`)
- Filter the material list by structural order, for example to find amorphous polymers that have no unit cell and so no CIF; needs prisma_cloud 0.6.23 or later (`api.v2.list_materials(structural_order=...)`)

### TEA / LCA data

- Process conditions now include their parameters, each with its value, units, description and reference, from prisma_cloud 0.6.23 (`api.v2.get_process_condition`)

### Reference catalog

- Get map coordinates for every source, sink and region in one call, with the reference and note saying where each location came from; servers older than prisma_cloud 0.6.22 return no references, notes or region coordinates (`api.v2.get_coordinates`)
- Add missing coordinates to existing sources, sinks and regions, with a dry run first; stored coordinates are kept unless you turn off `only_missing`, and no new records are created; needs prisma_cloud 0.6.22 or later (`api.v2.upsert_coordinates`)
- Generic properties can be filtered by the type of record they belong to, since object ids repeat across record types; needs prisma_cloud 0.6.23 or later (`api.v2.get_properties(content_type=...)`)

### PSDI

- PSDI material lists can be filtered by one or more structural orders; needs prisma_cloud 0.6.23 or later (`api.v2.get_materials_psdi(structural_order=...)`)

# v0.4.7

https://github.com/RCCS-CaptureTeam/prisma_api/releases/edit/v0.4.7

_Released 2026-11-04_

### Case studies & scenarios

- Screening results from v1 case studies can now be sent to the platform one batch at a time, with each case study and set of conditions stored as a scenario and its output KPIs replaced (`api.v2.ingest_screening_outputs`)
- Batches are processed on the server in the background while the client shows progress, and you can check a batch sent earlier at any time (`api.v2.screening_outputs_ingest_status`)
- New `prisma-outputs` command lists the batches in a results folder, sends some or all of them after asking, and reports the status of past uploads (`prisma-outputs list`, `send`, `status`)

### Datasets

- Bring your own dataset: send a folder of your own CSV, JSON or YAML results to an existing platform dataset, described by one `prisma_manifest.yaml`, with a dry run before anything is written (`api.v2.ingest_dataset`, `get_dataset_targets`)
- New `prisma-dataset` command sends the folder's structure (paths and sizes only), lets you tick the files to include on the dataset's page, then checks, packs and uploads just those files (`prisma-dataset tree`, `ticked`, `send`)
- Claude Code can write and check the manifest for you: `prisma-dataset install-skill` adds a `/prisma-dataset` command that builds the manifest for the ticked files and sends it once you confirm (`prisma-dataset install-skill`)
- Datasets keep a version history: re-sending changed data bumps the minor version, adding or removing files creates a new major version, and each version records what changed (`api.v2.list_dataset_versions`, `prisma-dataset versions`)
- Browse what was loaded: analysis runs from dataset uploads with their rows, and isotherm files with one column per pressure stored as proper isotherm records (`api.v2.list_analysis_runs`, `get_analysis_run_rows`, `list_dataset_trees`)

### Docs & examples

- The README now explains environment-variable setup, choosing production or a local dev server with `init(local_dev=...)`, and lists every v2 method, with links to the new per-series release notes (`prisma_api.init`)

### Packaging

- Installing the package now adds the `prisma-dataset` and `prisma-outputs` commands, and ships the manifest guide and Claude Code skill they use

# v0.4.6

https://github.com/RCCS-CaptureTeam/prisma_api/releases/edit/v0.4.6

_Released 2026-10-20_

### Case studies & scenarios

- The case-study library maintained in PrISMa_Platform (case studies, sources, sinks, regions, equipment and TEA tables) can now be synced to the platform in one call, replacing the old ZIP upload (`api.v2.upsert_case_study_library`)
- Large library uploads are split into smaller requests in a safe order, and a sync that stops partway can simply be re-run to finish (`max_request_bytes`)
- Try a sync first without saving anything, and see exactly which entries were rejected and why (`dry_run=True`, `raise_on_error=True`)
- Export the whole library, selected sections or one fully nested case study, in the same format the sync accepts (`api.v2.get_case_study_library_bundle`, `get_case_study_bundle`)
- Check when the library was last synced, browse past syncs and list records that have gone stale (`api.v2.latest_case_study_library_sync`, `list_case_study_library_sync_runs`, `list_stale_case_study_library_records`)

# v0.4.5

https://github.com/RCCS-CaptureTeam/prisma_api/releases/edit/v0.4.5

_Released 2026-10-06_

### AutoPrism

- CIF files from AutoPrism runs can now be uploaded directly, and collection uploads send their CIFs along automatically so structures and results land on the same material (`api.v2.upsert_autoprism_cifs`, `upsert_autoprism_collection`)
- AutoPrism lookups can match names exactly instead of partially (`match="exact"`)

### Adsorption & property data

- Hydrogen isotherms now live in the general adsorption isotherm table, so one set of methods reads and writes all isotherm data (`api.v2.get_adsorption_isotherm`, `upsert_adsorption_isotherm`)
- Deprecated: the separate hydrogen isotherm methods and the `isotherm_H2s` collection key still work but now warn; switch to the adsorption isotherm methods (`api.v2.*_isotherm_h2*`)

# v0.4.4

https://github.com/RCCS-CaptureTeam/prisma_api/releases/edit/v0.4.4

_Released 2026-10-02_

### AutoPrism

- Changed: rows the server rejects during an AutoPrism upload now trigger a warning naming the failed rows and are listed in the result, instead of passing unnoticed or raising a generic HTTP error (`PrismaRowErrorWarning`)
- Uploads can be made strict, so any rejected row raises an error you can catch (`raise_on_error=True`, `PrismaUpsertError`)
- Missing linked IDs are caught before anything is sent, saving a failed round trip (`check_ids=True`)
- Collection uploads now report rejected rows and partly failed sections in their summary (`api.v2.upsert_autoprism_collection`)
- You are warned when an upload contains fields the server doesn't recognise or creates new structures (`PrismaUnknownFieldsWarning`, `PrismaNewStructureWarning`)

### Adsorption & property data

- Full adsorption isotherms (not just single points) can now be read and uploaded, and are included in AutoPrism collections (`api.v2.get_adsorption_isotherm`, `upsert_adsorption_isotherm`)

# v0.4.3

https://github.com/RCCS-CaptureTeam/prisma_api/releases/edit/v0.4.3

_Released 2026-10-02_

### AutoPrism

- Uploads now record where the data came from (your own repository, version and commit) instead of prisma_api's, and you can pass that information in yourself (`meta_provenance`, `repo_dir`)
- Collection uploads report which sections failed and can optionally stop with an error (`api.v2.upsert_autoprism_collection(raise_on_error=True)`)

### Setup & configuration

- The client can now run without a config file, reading its API keys from environment variables, which makes it usable in CI and scripts (`PRISMA_API_KEY`, `PRISMA_API_DEV_API_KEY`, `PRISMA_API_DEV_HOST_PORT`)
- In non-interactive environments a missing key now raises a clear error naming the variables to set, instead of waiting for input (`RuntimeError`)
- `init()` now prints whether it connected to production or a local dev server, so test uploads don't reach production by mistake (`prisma_api.init(local_dev=True)`)
- Large uploads can be given more time, and values such as NaN or infinity are cleaned before sending so they no longer break uploads (`init(upload_timeout=300)`)

# v0.4.2

https://github.com/RCCS-CaptureTeam/prisma_api/releases/edit/v0.4.2

_Released 2026-09-30_

### Materials & structures

- Material bundles can now be uploaded as well as downloaded, using the same format the download returns, with CIF files attached (`api.v2.upsert_material_bundles`)
- Structural details such as formulae, cell parameters and space group are filled in automatically from each attached CIF (`derive_cif_metadata`)
- Bundles can be copied from one database to another, with local checks for unknown sections and a warning listing any bundles that failed (`strip_ids`, `tag_names`)

### Docs & examples

- New AutoPrism demo walks through uploading each table, uploading a whole collection and reading the results back (`examples/demo_autoprism.py`)

# v0.4.0

https://github.com/RCCS-CaptureTeam/prisma_api/releases/edit/v0.4.0

_Released 2026-09-17_

### AutoPrism

- AutoPrism results can now be read from and uploaded to the platform from Python, table by table (`api.v2.get_*` / `upsert_*` for each AutoPrism table)
- Fetch everything AutoPrism holds for a material or workflow in one call, with empty or unavailable tables handled gracefully (`api.v2.get_autoprism_collection`)
- Upload a full AutoPrism collection in one call, with a per-section summary of what was saved, skipped or failed (`api.v2.upsert_autoprism_collection`)
- Uploaded rows are stamped with provenance details (source repository, version and commit) automatically (`meta_provenance`)

### Adsorption & property data

- New read and upload methods for single-point adsorption, heat capacity, hydrogen isotherms, mofchecker results and zeo++ metrics, accepting a DataFrame, a list of records or a single record (`api.v2.get_adsorption_singlepoint`, `upsert_heat_capacity`, `upsert_zeopp_metrics`)
- Track AutoPrism computation runs by workflow, step and status (`api.v2.get_computation_runs`, `upsert_computation_runs`)
